# 镜头后端路由

## 选择原则

按镜头需求选择工具，不按题材绑定工具。一个产品广告可以同时包含 AI 生成主视觉、真实产品图、动态文字和既有音乐；一个科普视频可以同时包含录屏、图表、旁白和 AI 示意镜头。

## 路由表

| 需求 | 后端 | 优势 | 注意事项 |
|---|---|---|---|
| 已有素材混剪 | 原始视频/图片 + 合成器 | 可控、保留真实性 | 检查格式、方向、授权和原声 |
| 文生视频 | GenerateVideo | 快速获得新镜头 | 身份/物理/文字可能不稳定 |
| 图生视频 | 首帧/参考图 + GenerateVideo | 构图与主体更可控 | 先检查首帧，参考图不保证完全一致 |
| 关键视觉与封面 | GenerateImage | 便于迭代静态画面 | 消耗生成额度，先确认 |
| 信息与数据动画 | HTML 合成（html_render.py）/ FFmpeg / Remotion / HyperFrames / PIL 静态卡片 | 文本和数据准确、可复现 | 不要把数据图交给视频模型随意生成 |
| 可编辑三维世界 | Blender/UE5/程序化三维 | 几何和相机稳定 | 需要资产、渲染环境与技术说明 |
| 动态图形、动态文字、UI/产品演示、线稿解说 | HTML 合成 + `scripts/html_render.py` → MP4 → `type: video` 镜头 | 确定性、可复现、文字准确 | 遵守合成契约（画面只由 t 决定），先出静帧 |
| 一镜到底发布片、功能演示 | HTML 合成 + 一镜到底方法（`one_take.md`） | 有承接、不像 PPT | 先写在动/静止/承接节拍表 |
| 解说与教程 | 录屏/图片 + 旁白 + 字幕 | 信息清晰 | 先保证可读性和音画同步 |

## GenerateVideo 使用规则

可用于文本生成短视频，或以首帧、尾帧、参考图片/视频/音频辅助生成。结果保存为 MP4，放入项目 `shots/`，耗时视模型而定。

- **生成会消耗用户的使用额度。调用前说明要生成的镜头数量与时长，等用户确认；不要编造价格。**
- 一次生成一个镜头；提示词对应一个主要动作。
- `prompt` 必填；参考素材使用实际存在的本地路径或可访问 URL。
- 分辨率、时长、画幅等参数以工具说明为准，不猜测支持值；竖屏项目要请求竖屏画幅，否则合成时会被裁切/加黑边。
- 生成自带的音频不是最终混音的替代品；最终仍需检查响度、原声和音乐。
- 保留每次输出，不覆盖旧版本；记录对应镜头 ID 和提示词。

## GenerateImage 使用规则

- **同样消耗使用额度；批量出图前先确认。**
- 用于首帧、角色/产品参考、背景、封面和静态信息素材。
- 需要保持一致时优先复用已确认的参考图，而不是每张重新描述一个版本。
- 生成后先检查文字、手部、产品结构和商标，再作为视频首帧。

## 连续性与降级

- 角色/产品连续：固定参考资产、外观描述、色彩和道具；使用同系列首帧。
- 场景连续：固定时间、天气、光向和关键布局。
- 动作失败：简化动作、缩短镜头、改成特写/远景，或使用首帧 + 轻运动。
- 文字失败：画面中不生成文字，后期用字幕/标题卡叠加。
- 多次生成仍不稳定：切换为可复现图形、三维或真实素材，不无限重试。

## 两个脚本怎么配合

- `scripts/video_pipeline.py`：**顺序镜头合成器**。把 `title` / `image` / `video` 镜头按顺序统一画幅帧率、拼接，再烧录字幕、混音乐、输出成片。
- `scripts/html_render.py`：**单镜头渲染器**。把一个遵守合成契约的 HTML 文件逐帧渲染成 MP4。
- 衔接方式：动态图形镜头先用 `html_render.py` 渲染到 `shots/xx.mp4`（尺寸与 `project.json` 的 `output` 一致），再在清单里写成 `{"type": "video", "source": "shots/xx.mp4"}`；字幕、音乐、响度统一交给 `video_pipeline.py`。不要在 HTML 里再画一遍字幕。
