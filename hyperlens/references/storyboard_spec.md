# 导演工作流：SPEC → 镜头表 → 故事板 → 审片 → 做坏方式

第 2 步里画面那一半的规则。故事那一半（素材、BRIEF、方案、主角、世界、节拍、剧本、故事验收）见 `story_pipeline.md`；本文件的 SPEC 在 2.5 末尾由 world.md 派生，镜头表在 2.8 由剧本推出。

> 方法来源（改写综合）：HyperFrames（Apache-2.0）story.md / spec.md / review.md；Lemo-Opuscar（MIT）DIRECTOR.md；huashu-art-motion（MIT）镜头表模板与「六种做坏方式」；OneTake（非商用许可，仅借鉴思路）。

## 1–2. 故事层（已移到 story_pipeline.md）

原来的“一件事”和“三个方案”已并入故事层 2.1–2.9，规则以 `story_pipeline.md` 为准，这里不再重复：
- “一件事” → 2.2 BRIEF 的“观众带走”；“一个具体例子贯穿全片” → 2.5 的贯穿物；“事实和创意分开、屏上说法追得到来源” → 2.1 事实卡和剧本里的 `[F#]`。
- “三个方案 STORYLINES.md”和“标杆作品（学什么/不拿什么）” → 2.3（数量按档位和题材：默认 3 个，教程 2 个，<15 秒不出）。
- 镜头表由 2.7 剧本推出（2.8），用户确认改为确认③（剧本 + 分镜）。

## 3. SPEC.md（形容词换成数字；2.5 末尾由 world.md 和主角卡派生）

```text
GOAL:    观众看完的感受或动作，一句话
OUTPUT:  后端（AI 视频 / HTML / Remotion / 素材混剪）、宽×高、fps
TIME:    秒 × fps = 帧；有音乐写 BPM 与每拍帧数
LOOK:    画风锁三行（见 style_lock.md）+ 字体/字号/字距 + 材质参数（颗粒%、阴影、暗角%）
OBJECTS: 观众必须认出来的每个物，以及让它不靠标签也认得出的材质和细节
MOTION:  按角色命名缓动（入场/移动/退场/镜头）；弹簧写阻尼比；时长与错峰写帧数
SHOTS:   每镜一行：帧区间、唯一主动作、观众读到什么（带时间窗）、声音、如何交给下一镜
BANNED:  默认禁用清单 + 本片额外不许变成的样子
QA:      要检查的帧及每帧必须显示什么
```

构图数字：主角占画面 ≥ 40%；一镜一个主动作，次要动作走 50–70% 距离、晚 100–200ms 启动，其余静止；故事片里每镜都推动下一镜（「所以……」「这意味着……」）；信息卡在约 2.5 秒内把信息放完然后停住，任何暂停帧都是一张完整海报。

## 4. 镜头表（在原 9 字段基础上新增 4 列；2.8 再加故事层列）

原字段 `id / 目的 / 画面 / 时长 / 来源 / 运动 / 声音 / 字幕 / 连续性` 保留，新增：

| 新列 | 写什么 | 不要写 |
|---|---|---|
| 物 | 名词：画面里能指着说「就是它」的东西 | 标题、要点、图标、背景、空镜 |
| 动作 | 动词：这个物自己在干什么 | 出现、显示、淡入、逐条出现 |
| 镜头 | 停 / 缓推 / 拉远 / 横移 / 快推 / 砸入 / 切 / 一镜到底 | 每镜都推一次 |
| 承接 | 跨到下一镜的幸存者（手、主体、容器、声音 J/L 切） | 空（除连击与落版） |

2.8 再加的故事层列（规则见 `story_pipeline.md` 2.8，模板见 `assets/storyboard.template.md`）：拍 / 关键（是/否）/ 角色 / 场景或界面状态 / 道具或元素 / 景别 / 预定后端（AI 视频 / AI 图 / HTML / 素材 / 标题卡）/ 剧本行号 / 首帧编号（第 3 步后填）。表头第一列保持“时间段”。

可用 `scripts/storyboard_lint.py` 检查画面规则（见下），`scripts/story_lint.py` 检查拍覆盖、角色一致等故事规则。写不出某一行的「物」和「动作」，说明这一镜还没想清楚，先别生成。

五条要求：
1. 开头 3 秒是一个具体小场景（一双手/一个物在做和题目有关的事），不是标题，不是「今天我们来讲」；第 0 帧就是封面。
2. 结尾落在主角/主物的一个动作上（合上书、拉远看全貌），呼应开头；落版 logo 被「带进来」而不是贴上去。
3. 一镜 2–6 秒（代码动画）或按后端能力（AI 视频单镜一般 3–8 秒）；镜头时长要有变化。
4. 文字主导的镜头 ≤ 30%；屏上字每镜 ≤ 8 个中文字，整句口播交给字幕。
5. 相邻两镜换构图或景别，不换画风。

## 5. 按需出故事板

用户要看时（附在确认③里一起发，不另增确认点），用**真实生产方式**（真实绘制代码或真实生成的首帧，不是示意草图）出 6–9 个关键镜头拼成一张联系表，每格写镜号、景别、时长、台词，连同一句话梗概和「最没把握的地方」一起发，等确认。用户没要就不停。

## 6. 审片（在原质检之前加）

1. 每个节拍帧用陌生人的口吻写一句话描述并点名每个物；需要解释才认得出的物是 P0 问题。
2. 按顺序读节拍帧：陌生人能否看懂、每一帧是否引出下一帧；和 SPEC 的 SHOTS 逐行对照。
3. 把画面里出现的默认套路逐条写进 BANNED 并修掉。
4. 每个切点前后 ±0.2 秒抽一条，检查空帧、跳变、主体丢失；关键帧再按手机宽度（360px）缩小看一次可读性。
5. 用正常速度带声音完整看一遍——运镜顺不顺，抽帧看不出来。
6. 如条件允许，派一个没参与制作的 agent 只看成片挑问题。
7. 一轮集中修完所有问题，再复查一次；交付后的意见是新的一轮，只改被要求的部分。

## 7. 最常见的做坏方式（开工前、交付前各对一遍）

1. 翻页 PPT：固定页框、要点逐条淡入、每镜同一个镜头动作、结尾回到居中金句卡。
2. 照搬示范/模板/上一支片的构图、角色、故事和画风。
3. 没有具体的物：抽象概念只写成字和图标。
4. 死背景、空画面、主体太小或贴边、字幕压住主体。
5. 有真实素材却用 AI 或代码去画。
6. 一眼 AI 味：蓝紫渐变、霓虹、粒子、每镜换画风的拼贴。
7. 节拍器式等长镜头，或每拍都替换上一拍、没有承接。
8. 笑点/反转/字太快看不懂；文字在被阅读时还在动。
