# 故事层：第 2 步 2.1–2.9（从素材到剧本、分镜、故事验收）

适用：所有题材（科普/历史、产品发布/功能演示、广告/品牌、教程、剧情短片/叙事、口播/解说、动态图形/信息卡、MV/氛围片）。换内容不换流程：最多 9 个小步骤，按“时长档 + 题材”删减，由 `scripts/story_lint.py --plan` 算出来，不让 agent 每次自己判断。

> 为什么有这一层：原来第 2 步的规则大多管**画面**（物、动作、镜头、承接），管故事的只有“一件事”和“每镜推动下一镜”，又没有验收门，片子容易做成“一条一条往下列”。本层在镜头表前补上故事，再加一道和逐镜验收对应的**故事验收门**。
> 相关：结构模板、钩子库和故事层做坏方式见 `story_structures.md`；SPEC 与审片见 `storyboard_spec.md`；画风锁见 `style_lock.md`；模板在 `assets/`（STORY / facts / BRIEF / world / outline / script / STORY_QC / storyboard / QC）。

## 0. 先算步骤清单

```bash
python3 scripts/story_lint.py --plan <project>/project.json      # 写回 story.plan；--dry-run 只打印
python3 scripts/story_lint.py <project>/                          # 写完 2.7/2.8 后检查，红灯先改
```

`project.json` 的 `story` 字段（第 1 步选择卡确认后填）：`genre`、`duration`，可选 `reveal`、`ai_image`、`ai_video`、`silent`（完全无声）、`has_facts`（剧情/MV 片中有真实事实）、`has_protagonist`（动态图形/MV 有拟人元素、贯穿图形或人物）。`plan` 由脚本写回：步骤清单、文件清单、确认点、lint 开关、验收权重、审阅预算。不新建 story.config.json。

## 一、通用 9 步流程

```
2.1 素材与事实卡 → 2.2 观众问题与目标 → 2.3 方案（比结构）【确认①】
→ 2.4 主角 → 2.5 世界 + SPEC/画风锁【确认②：只看文字卡】
→ 2.6 节拍大纲 → 2.7 剧本 → 2.8 切分镜（含预定后端）
→ 2.9 故事验收（独立审阅打分）【确认③：剧本 + 分镜】
→ 第 3 步后端路由（细化）→ 参考图/首帧确认 → 试拍 …（原流程）
```

实际做哪几步、写哪几个文件、确认几次，由“时长档 + 题材”决定（第三节），用第 0 节的 `--plan` 算出。

### 文件（按档位合并，配置不单独建文件）

题材、时长、步骤清单、lint 开关和验收权重都写进现有 `project.json` 的 `story` 字段，不新建 story.config.json。

| 档位 | 故事层文件 | 个数 |
|---|---|---|
| <15 秒 | `STORY.md`（问题 + 钩子 + 2–4 拍 + 剧本 + 一行主角/世界）、`镜头表.md` | 2 |
| 15–<45 秒 | `STORY.md`（素材/事实卡 + BRIEF + 主角与世界卡）、`STORYLINES.md`、`script.md`（含“功能”列，替代大纲）、`镜头表.md`、`STORY_QC.md` | 5 |
| 45–<90 秒、≥90 秒 | `research/facts.md`、`BRIEF.md`、`STORYLINES.md`、`world.md`（主角卡 + 世界卡 + 由它派生的 SPEC/画风锁）、`outline.md`、`script.md`、`镜头表.md`、`STORY_QC.md` | 8 |

AI 生成项目另有 `PROMPTS.md`（统一的提示词文件，lint 检查一致性描述用）。

### 时间与审阅预算

2026-10-30 用两个题材试跑到剧本和分镜（不生成）：30 秒功能演示、90 秒科普。文件在仓库 `examples/`（不要放进技能目录），记录见 `examples/TRIAL.md`。

| 档位 | 写作（不含确认等待、不含生成） | 端到端（含确认等待，未实测等待时长） | 故事审阅调用上限 |
|---|---|---|---|
| <15 秒 | 未跑，仍约 10 分钟 | 约 10 分钟 | 3 次（没有方案可换） |
| 15–<45 秒 | 这次和 90 秒那支一起，从动笔到 lint 通过约 6 分钟（见 examples/TRIAL.md）。规划时写作按约 15 分钟留余量，不要把 6 分钟当成常态 | 仍按 20–30 分钟（确认①③的等待这次没发生） | 4 次 |
| 45–<90 秒 | 未单独跑 | 约 40–60 分钟 | 4 次 |
| ≥90 秒 | 试跑里写完全套文件（含两幕）明显短于「60 分钟 + 每幕 15 分钟」；纯写作按 30–40 分钟估 | 60 分钟 + 每多一幕 15 分钟留作上限（事实核对和确认②算在里面） | 整片 4 次，另每幕局部复审 ≤2 次 |

审阅调用上限 = 首审 1 + 重写复审 ≤2 + 回到 2.3 后 1（<15 秒没有回到 2.3 这一步）。用完就按 2.9 的“封顶后交给用户”处理，不再继续循环。

通过线不改：加权平均 ≥7，单项 ≥5，无 P0。两支都是一次首审通过，没有低分样本，不能靠这次把 7 调高或调低。这次的审阅和写作是同一个 agent 分两遍看（先剧本和镜头表，再对照 BRIEF），不是另一个进程。

### 2.1 素材与事实卡
- **目的**：故事从真东西里长出来：真实事实、真实产品输出、真实步骤、真实品牌信息。
- **通用规则**
  - 每条一行：编号 F# / 内容 / 来源（链接、文件、截图、用户提供）/ 可信度 / 能当什么用（钩子、冲突、转折、证据、结尾）。
  - 至少找 3 条“有张力”的素材：反常识的事实、前后对比、用户真实痛点、出乎意料的结果。
  - 屏上出现的每个说法、数字都要追得到来源；示意数据标“示意”。
- **按题材**
  - 科普/历史：学术或权威来源，标共识/有争议；改编书籍时作者观点单独一栏。书不在手边时，按“例 C”的来源规则处理。
  - 产品/功能演示：真实界面截图、真实输出、更新日志；不写没验证过的效果。
  - 广告/品牌：品牌规范、卖点清单（每个卖点附依据）、禁用说法（含广告法禁用的极限词）。
  - 教程：按下面的“教程实测规则”。
  - 剧情/MV：不需要事实卡，换成“灵感卡”：参考作品（学什么/不拿什么）、情绪关键词、歌词或主题。片中若出现真实事实，照样写 F#。
  - 口播/解说：要讲的观点 + 支撑每个观点的证据。
- **教程实测规则**
  1. 能在 box 上安全跑的（命令行、开源工具、不需要账号、不改动用户数据），就实跑，记下真实命令、输出和报错。
  2. 跑不了的（依赖用户自己的电脑、付费软件、需要登录、GUI 操作、有破坏性），请用户提供录屏、截图或真实输出。这一步可以和确认①放在同一条消息里问，不另增确认点。
  3. 用户也给不了的，该步标“未实测”：剧本里该步加 `[未实测]`，“屏幕结果”栏只能写示意并标“示意”，不编造真实画面；交付说明里列出所有未实测步骤。
  4. 未实测不算 P0，但“可复现”一项最高只给 6 分（见第四节）。

### 2.2 观众问题与目标
- **目的**：把“一件事”从一句结论改成**一个问题 + 一个答案**，再加一个看完的目标。第 1 步选择卡确认的平台、时长、画幅等不在这里重写，直接引用。
- **模板（BRIEF.md；<45 秒写进 STORY.md）**
  ```text
  观众是谁：
  观众问题：观众看到开头会在心里问的那个问题（MV 写“情绪命题”）
  答案：片子给出的那一句（用观众的话）
  揭晓方式：悬念型 / 结果先行型
  目标：看完的感受（情绪片）或动作（产品、广告、教程）
  情绪路线：开头____ → 中段____ → 结尾____
  观众带走：看完会转述给别人的那一句（= 原来的“一件事”）
  ```
- **揭晓方式**
  - 悬念型（默认：科普/历史、剧情、多数口播）：开头抛出问题，答案到结尾才完整给出。
  - 结果先行型（产品、广告、教程，动态图形可选）：开头先给结果或承诺，中段讲“怎么做到”，结尾给出行动或下一步，并回扣开头的结果。
- **按题材的“观众问题”长什么样**
  - 科普/历史：“为什么……？”
  - 产品/功能：“这个能帮我省掉哪件麻烦事？”
  - 广告：“这跟我有什么关系？”
  - 教程：“我怎么才能做到……？”（答案就是做出来的结果）
  - 剧情：“TA 最后会怎样？”
  - MV/氛围：不是问题，而是一个“情绪命题”（例：“离开的那一刻”）

### 2.3 方案：比结构，不只比画面
- **数量**：默认 3 个；教程出 2 个；<15 秒不出多方案（直接写推荐方案，回复里用一句话提一个备选）。
- **每个方案必填**：一句话 logline（谁 + 想要什么 + 被什么挡住 + 结果）、结构模板（见第二部分）、钩子画面 + 第一句、主角类型、冲突或阻力、转折、结尾回扣、画风一行、声音一行、可拍性风险。
- **产品发布/功能演示/一镜到底**：每个方案的“画风一行”换成 one_take.md 的“中心画面创意”，不再另出三个创意（避免同一件事做两遍）。
- **规则**：方案之间的结构、主角类型、钩子类型三项里至少两项不同；推荐理由写“为什么这个讲法最能回答观众问题或达成目标”。
- **标杆作品**（沿用原规则）：给推荐方案找 1–2 部标杆作品，写“学什么/不拿什么”。
- **确认①**：只问选哪个方案，可以直接说“你定”。

### 2.4 主角（拆角色）
- **目的**：给观众一个能跟的“人”，并给生成或渲染一个固定外观。主角不一定是人。
- **主角类型**
  | 类型 | 适用 | 例子 |
  |---|---|---|
  | 真人角色 | 剧情、广告、部分科普历史 | 一个顾客、一位历史场景里的虚构人物 |
  | 用户画像 | 产品、功能演示、教程 | “第一次做视频的运营小李” |
  | 产品即主角 | 产品发布、品牌 | 一个按钮、一个 App、一件商品 |
  | 叙述者 | 口播、解说 | 出镜人或画外音的“我” |
  | 拟人化概念/物件 | 科普、动态图形 | 一个数据包、一粒光点、一枚硬币 |
  | 观众“你” | 教程、广告、第二人称科普 | “你打开文件夹……” |
  | 群体 | 历史、社会话题 | 一个部落、一座城 |
- **通用角色卡模板**（写在 world.md 或 STORY.md 里，不单独建文件）
  ```text
  ID / 类型：
  身份：
  欲望（想要什么）：
  障碍（被什么挡住）：
  转变（开头____，结尾____）：
  视觉锚点：2–3 个不靠脸也能认出的特征（颜色、形状、饰物、图标、界面元素）
  一致性描述：一段固定外观描述，生成或渲染时逐字复用（写进 PROMPTS.md）
  可拍方式：AI 生成正脸 / 只拍手和背影 / 剪影 / HTML 图形 / 真实录屏
  ```
- **规则**：主角 1–2 个；AI 拍真人时视觉锚点放在手、服装、饰物上，不放在五官上；非人主角也要有欲望、障碍和转变（例：“产品”的欲望是帮用户把 10 步变成 1 步）。参考图不在这一步出（见 2.5）。

### 2.5 世界 + SPEC/画风锁
- **目的**：一份文字版视觉 bible，让每个镜头都在同一个世界里。
- **按题材，“场景与道具”分别指什么**
  | 题材 | 场景 | 道具 / 元素 |
  |---|---|---|
  | 实拍感（剧情、历史、广告） | 地点、时代、天气、光线 | 关键道具、服装 |
  | 产品/功能演示、教程 | 界面状态（空状态、操作中、完成、报错） | 按钮、光标、弹窗、真实数据样例 |
  | 动态图形/信息卡 | 版式网格、背景层 | 图形元素库（形状、图标、图表类型）、动效规则 |
  | 广告/品牌 | 使用场景 | 品牌资产（Logo、色值、字体、口号、产品外观） |
  | 口播/解说 | 出镜环境或背景板 | 字卡样式、图示、B-roll 清单 |
  | MV/氛围 | 情绪空间（颜色、天气、时间） | 意象（反复出现的物） |
- **每张卡写**：ID / 外观或状态 / 光线或配色 / 必有元素 / 禁止出现的东西（时代穿帮、竞品、未授权素材）/ 首次出现在哪一拍。
- **贯穿物（推荐）**：钩子、中点、结尾都出现，每次意义有变化；可以是物件、光标、一个数字、一种颜色。≥15 秒缺贯穿物时 lint 给黄灯，在交付说明里写理由；<15 秒不检查。
- **规则**：场景或界面状态 3–5 个，复用优先；禁止项写进生成提示词的 negative。
- **派生 SPEC 与画风锁**：world.md 写完后，按原 style_lock.md / storyboard_spec.md 的规则写 SPEC（LOOK / MOTION / SHOTS / BANNED / QA）和镜头表前的画风锁三行（画风、色板、角色），规则不变，只是来源改成 world.md 和主角卡。
- **确认②（只在 ≥45 秒）**：只发文字版的“主角与世界卡”和画风锁三行，**不出图、不消耗生成额度**。参考图和首帧放到 2.9 通过、第 3 步后端路由之后，与原来的“静帧/首帧确认”合并成一次（确认④）；HTML/图形/素材路线没有参考图，这一步跳过。

### 2.6 节拍大纲
- **目的**：在写台词之前先排好“信息何时给、情绪怎么走”。15–<45 秒并入 2.7（剧本表加“功能”列）。
- **节拍表模板**
  | 拍 | 时间 | 功能 | 连接词 | 发生了什么 | 观众得到的信息 | 张力 −5…+5 | 贯穿物状态 | 音乐段落（有音乐时） |
  |---|---|---|---|---|---|---|---|---|
- **通用规则**
  - “连接词”列写本拍和上一拍的关系：但是/所以/于是；教程的步骤可以写“接着”，但这一拍必须写清“为什么要这一步”。
  - 时长分配参考：钩子 5–10%，铺垫 15–20%，展开 30–40%，转折 10–15%，高潮或结果 15–20%，收尾或行动 5–10%；按结构模板调整。
  - 至少一次张力变化：叙事类是情绪下沉，产品和教程是“卡住/报错/旧办法失败”，MV 是一次节奏或画面上的反差。
  - 信息密度、呼吸拍按常量表。
  - 一镜到底类片子：把 one_take.md 节拍表的“在动 / 静止 / 承接”作为附加列写进这张表，不另写一张表。
  - MV 和有音乐的片子：“音乐段落”列手工标注每段起止秒数（来自用户提供的歌曲结构或人工听标），lint 只比对这里写的数字。
  - ≥90 秒按幕分段时，拍编号写 A1-B1 这种。用标题把大纲拆成多张表也可以：`story_lint.py` 会把同一文件里的节拍表拼在一起，第二幕不会被丢掉。

### 2.7 剧本
- **目的**：先写剧本，再从剧本里切镜头。
- **通用栏**：拍 / 画面（观众看到什么）/ 旁白·台词·屏上字 / 声音 / 预计时长（15–<45 秒加“功能”列）
- **按题材的剧本形态**
  | 题材 | 剧本骨架 |
  |---|---|
  | 科普/历史 | 问题 → 常识 → 反常识 → 证据 → 新理解 → 回到观众 |
  | 产品/功能演示 | 结果或痛点先行 → 用户卡住的场景 → 旧办法 → 产品介入（真实操作）→ 结果 → 下一步 |
  | 广告/品牌 | 痛点 → 转折 → 卖点（每个附依据）→ 行动号召 |
  | 教程 | 先看结果 → 每一步写“操作 + 屏幕上的结果 + 为什么” → 常见坑 → 再看结果 |
  | 剧情短片 | 欲望 → 障碍 → 尝试失败 → 转折 → 代价 → 新状态 |
  | 口播/解说 | 观点钩子 → 3 个论点（各配证据和画面）→ 反方或误区 → 结论 |
  | 动态图形/信息卡 | 一个数字或问题 → 拆开 → 对比 → 一个结论画面 |
  | MV/氛围 | 按音乐段落（前奏/主歌/副歌/桥段）排意象与情绪，不写旁白 |
- **通用规则**（数字一律见常量表）
  - 口播速度、旁白占比、屏上字按常量表。
  - **展示不要告诉**：画面已经拍出来的不要再说；每句都问“删掉它观众还看得懂吗”。
  - 第一句按揭晓方式写：悬念型是问题、反差或悬念；结果先行型是结果或承诺。最后一句回扣第一句或给出行动，不喊口号。
  - 叙述视角从头到尾一致（我/我们/你/角色）。
  - 事实或卖点句后标 `[F#]`，对应事实卡；教程未实测的步骤标 `[未实测]`。
  - **声音转折（推荐）**：至少一处用声音做转折（静音、节奏停顿、音效、环境声）。选择卡选了“无旁白 + 无音乐”时也可以用静音或环境声；缺少时 lint 给黄灯，选择卡选了“完全无声”时关闭这项检查。

### 2.8 切分镜：由剧本推出镜头表
- **新增列**：拍 / 关键（是/否）/ 角色 / 场景或界面状态 / 道具或元素 / 景别（远、全、中、近、特写；界面类写“全屏、局部放大、组件特写”）/ **预定后端**（AI 视频 / AI 图 / HTML / 素材 / 标题卡）/ 剧本行号 / 首帧编号（第 3 步后填）
- **规则**
  - 每拍至少 1 个镜头，每个镜头只属于一拍。
  - “关键”列标出故事关键镜头（钩子、转折、高潮、结尾），逐镜验收时受保护（见第六节第 2 条）。
  - **预定后端**：按 backend_routing.md 的速查表先给每镜一个预定后端，“可拍性”就按预定后端判断。AI 难拍的动作（正脸、多人互动、手部精细操作）、难重建的界面状态，在这一步就换成可拍的表达，或给关键镜头换一个能稳定做出的后端。
  - 第 3 步只是细化预定后端；如果第 3 步改了关键镜头的后端或画面动作，要回到这里改表，并对受影响的拍重跑 2.9 的局部复审。
  - 原有的物、动作、镜头、承接列和 storyboard_lint 规则全部保留。

### 2.9 故事验收
- **审阅者**：新开一个只读文字的子 agent，没参与 2.1–2.8。
- **输入隔离（两轮）**
  1. 盲读：只给 `script.md` 和 `镜头表.md`（<45 秒给 STORY.md 里的剧本部分 + 镜头表），不给 BRIEF、STORYLINES、大纲和事实卡。审阅者用陌生人口吻复述：观众问题（或情绪命题）、主角和 TA 想要什么、结尾给了什么、观众会带走的那一句。
  2. 对照：再给 BRIEF、事实卡、大纲和 `project.json` 的 `story` 字段，审阅者对照复述与 BRIEF 的差距，按第四节评分并检查 P0。
- **判定**：按第四节的权重和通过线判定，记录写进 STORY_QC.md（版本号、两轮输出、各项分数、P0、改了哪几拍）。
- **不通过时（封顶，不循环）**
  1. 只重写低分的拍，复审，最多 2 轮。
  2. 仍不过：回到 2.3 换方案，最多 1 次（<15 秒没有多方案，跳过这一步，直接到第 3 步）。用户之前说过“你定”就自动取次推荐方案；否则把失败原因和新方案一起发，这是故事层唯一可能多出的一次确认。
  3. 换方案后再审一次仍不过：停下，把分数表、低分的拍、审阅者的复述发给用户，请用户二选一：(a) 按当前最高分版本继续，在交付说明里标出风险；(b) 用户调整方向或补充素材后重来。
- **确认③**：剧本和镜头表一起发，附审阅者的一句话复述和分数，只问“故事对不对、要改哪一拍”。它替代原来 SKILL.md 第 2 步末尾的“分镜表发给用户看一眼”；用户要看故事板时，按 storyboard_spec.md 第 5 节附在这里。

## 三、时长分档与题材路由

### 优先级
1. 时长档先定上限：最多做哪些步骤、写哪些文件、确认几次。
2. 题材只在档内删减或改写，不增加步骤，也不增加确认次数。
3. 两者冲突时，合并方式按时长档，写什么内容按题材。
4. 最终清单由 `story_lint.py --plan` 算出，写进 `project.json` 的 `story.plan`。

### 按时长分档（左闭右开）

## 四、故事验收：评分、权重与 P0

### 通用核心项（每项 0–10）

| 项 | 看什么 |
|---|---|
| 钩子 | 前 3 秒是否让人想继续看 |
| 问题/目标 | 审阅者盲读时能否复述观众问题或片子要观众做什么 |
| 主角 | 能否说出主角是谁或是什么、想要什么 |
| 因果链 | 拍与拍之间有“所以/但是”，删掉任何一拍都会断 |
| 展示 | 画面在讲故事，旁白和屏上字不复述画面 |
| 节奏与信息密度 | 有起伏、有停顿，信息不过载 |
| 结尾 | 按揭晓方式回答了问题或给出行动，并回扣开头 |
| 真实 | 事实、数据、卖点都有来源，措辞不夸大 |
| 可拍性 | 关键镜头能用“预定后端”稳定做出来 |

### 每个题材的完整权重表

附加项同样 0–10 分，计入平均。“×2 项”只从本行的核心项和附加项里选，其余项 ×1。

| 题材 | 附加项 | ×2 项 | N/A 项 | 改判口径 |
|---|---|---|---|---|
| 科普/历史 | 证据支撑、争议标注 | 真实、因果链、结尾 | 无 | — |
| 产品/功能演示 | 操作可见、卖点出处 | 真实、可拍性、结尾 | 无 | 结尾 = 给出下一步 |
| 广告/品牌 | 品牌一致、行动合规 | 钩子、品牌一致、结尾 | 无 | 结尾 = 行动号召 |
| 教程 | 可复现、每步有结果、常见坑 | 可复现、每步有结果、节奏与信息密度 | 无 | 有未实测步骤时“可复现”最高 6 分 |
| 剧情短片 | 冲突与代价、转折 | 主角、因果链、冲突与代价 | 真实（片中没有真实事实时） | 问题/目标 = 能否说出“TA 想要什么、最后怎样” |
| 口播/解说 | 论点清楚、反方或误区 | 论点清楚、展示、真实 | 无 | — |
| 动态图形/信息卡 | 承接、手机可读 | 承接、手机可读、节奏与信息密度 | 主角（没有拟人元素或贯穿图形时） | — |
| MV/氛围 | 卡段落、意象回扣 | 卡段落、意象回扣、结尾 | 真实（没有真实事实时）；主角（没有人物时） | 问题/目标 = 情绪命题；结尾 = 情绪落点；因果链 = 段落之间的情绪递进 |

### 判定规则
- 加权平均 = Σ(分数 × 权重) ÷ Σ权重，N/A 项不计入分子和分母。
- 通过：加权平均 ≥ 7，所有非 N/A 项（含附加项）都 ≥ 5，且没有 P0。
- N/A 只能用上表列出的项，审阅者不能自己判 N/A；剧情或 MV 里只要出现真实事实，“真实”就恢复打分。
- <15 秒只打：钩子、结尾、真实，再加本题材 ×2 项里的第一项；“真实”是 N/A 时省略。通过线相同。
- ≥90 秒：每幕按同一张表打分，整片再打一次，都要通过。

### P0（有一个就不通过）

| 适用 | P0 |
|---|---|
| 所有题材 | 事实、数据或卖点错误；没有来源的说法被当成事实写 |
| 科普/历史、口播/解说 | 盲读复述不出观众问题；结尾没有回答问题 |
| 产品/功能演示、广告/品牌 | 复述不出“它帮观众解决了什么”；没有行动或下一步；卖点没有依据；用了禁用说法 |
| 教程 | 已实测的步骤照着做失败；关键步骤没有屏幕结果；步骤前后矛盾（未实测不算 P0，按上面的规则限分） |
| 剧情短片 | 复述不出主角想要什么；结尾主角没有新状态 |
| 动态图形/信息卡 | 复述不出那个核心数字或结论 |
| MV/氛围 | 复述不出情绪命题；画面变化和标注的音乐段落完全对不上 |

## 五、lint 扩展：自动检查与人工检查

`scripts/story_lint.py` 只用 Python 标准库（jieba 可选），按 `project.json` 的 `story.plan` 开关检查项；红灯非零退出。规则依赖下面这些结构化字段：
- 节拍表的“连接词”“张力”“贯穿物状态”“音乐段落”列；
- 镜头表的“拍”“关键”“角色”“预定后端”列；
- PROMPTS.md 按角色 ID 分节；
- `shots/QC.md` 新增“关键”“动作改动”“故事复核”三列。

字段写法（脚本按这些认）：
- 剧本表头含“拍”和“画面/旁白/操作/意象”之一；节拍表头含“拍”和“功能/连接词/张力/发生了什么”之一；15–<45 秒、产品、动态图形的节拍列直接写在剧本表里。
- 每拍时长写在剧本“时长”列（秒），或节拍表“时间”列（`0–6`）。
- 事实/卖点句：含阿拉伯数字、两位及以上的数量（八个、三步、两次）、年/倍/百分比/时长、比较级，或“最/第一/唯一”（不含“最多/最后/最近/最初/最终”，也不含“一个/一次/第一步”）的句子，句末要有 `[F#]`；纯示意写 `[示意]`。
- 角色卡写 `ID / 类型：C1 / …` 和 `一致性描述：…`；PROMPTS.md 用 `## C1` 分节，逐字放入一致性描述。
- 品牌卡是 world.md 里标题含“品牌卡”的小节，写 `#RRGGBB` 色值和 `字体：A、B`。
- 音乐段落列写段落名 + 起点秒数（`副歌 32.0`）。
- QC.md 的“故事复核”写 STORY_QC 版本号（`v2`），该版本要在 STORY_QC.md 里出现。

### 自动检查

| 检查 | 规则 | 依据字段 | 默认开启的题材 | 级别 |
|---|---|---|---|---|
| 节拍覆盖 | 每拍 ≥1 镜，镜头引用的“拍”都存在 | 镜头表“拍” | 全部 | 红 |
| 阅读速度 | 每拍旁白超过常量表红线 | 剧本旁白 + 时长 | 有旁白的题材 | 红 |
| 旁白占比 | 超过常量表上限 | 剧本 | 有旁白的题材 | 黄 |
| 因果连接 | “连接词”列为“然后”或为空的比例 > 50% | 节拍表“连接词” | 叙事、科普、产品、广告、口播 | 黄 |
| 年表味 | 以年代或时间开头的旁白句 > 30% | 剧本旁白（正则） | 科普/历史 | 黄 |
| 步骤完整 | 教程缺“操作/屏幕结果”列，或有操作没有屏幕结果。功能演示只查功能里含“介入/操作/演示/步骤”的拍 | 剧本栏 | 教程、功能演示 | 教程为红；功能演示的操作拍为红，整表缺列为黄 |
| 未实测 | 有 `[未实测]` 的步骤 | 剧本 | 教程 | 黄（交付说明必须列出） |
| 卖点依据 | 卖点句缺 `[F#]` | 剧本 | 产品、广告 | 红 |
| 事实来源 | 事实句缺 `[F#]`，或编号在事实卡里不存在 | 剧本 + 事实卡 | 科普、历史、口播 | 红 |
| 张力变化 | 张力值全程单调或全相同 | 节拍表“张力” | 全部（<15 秒关闭） | 黄 |
| 贯穿物 | 没出现在第一拍、中点、最后一拍 | 节拍表“贯穿物状态” | ≥15 秒（推荐项） | 黄 |
| 声音转折 | 没有任何一拍用声音做转折 | 剧本“声音”栏 | 全部（选择卡选了完全无声时关闭） | 黄 |
| 主角一致 | 角色 ID 不存在，或 PROMPTS.md 里该角色的提示词缺一致性描述 | 镜头表“角色” + PROMPTS.md | 用 AI 生成角色的项目 | 红 |
| 品牌资产 | 色值或字体不在品牌卡里 | world.md + 镜头表/HTML | 广告、产品 | 黄 |
| 段落对齐 | 拍的起点和手工标注的音乐段落偏差 > 0.5 秒 | 节拍表“音乐段落” | MV、标注了段落的片子 | 黄 |
| 关键镜头保护 | QC.md 里“关键=是、动作改动=是”，但“故事复核”为空或指向不存在的 STORY_QC 版本 | shots/QC.md + STORY_QC.md | 全部 | 红 |
| 结构模板 | 节拍“功能”缺少模板要求的环节（例：广告缺“行动”） | 节拍表/剧本“功能” | 全部 | 黄 |

### 人工检查（交给 2.9 审阅者，写进审阅清单）

| 检查 | 为什么不自动 | 怎么做 |
|---|---|---|
| 复述画面（旁白和画面栏说的是同一件事） | 要中文分词和语义判断，默认环境没有分词库 | 审阅者在“展示”一项里逐拍判断；装了 jieba 时 story_lint 额外给名词重合率作参考（黄灯） |
| 音乐段落识别 | 没有自动识别歌曲结构的工具 | 用户提供歌曲结构，或 agent 听标后手工写进“音乐段落”列，再由自动检查比对 |

`video_pipeline.py doctor` 增加一项**可选**依赖检查：jieba（缺少时只提示“复述画面改为纯人工”，不报错）。

## 六、其他通用改进

1. **结构模板库**：8 种结构的模板、原创中文样例和“做坏方式”见 `story_structures.md`。
2. **关键镜头保护（规则同 shot_qc.md）**：镜头表“关键=是”的镜头，重做时不能直接用“改拍背影/剪影”“改拍结果而非过程”“去掉动作”这类改变故事动作的策略。先试不改动作的修法：锁关键帧再图生视频、首尾帧都锁、换景别、换后端（HTML、实拍素材）。确实要改动作时，先改 script.md 对应的拍，对受影响的项（钩子、因果链、结尾和复述）做 2.9 局部复审，过了再生产。QC.md 记“动作改动=是”和“故事复核=STORY_QC 版本号”。如果审阅者判定故事意思变了，在确认⑤的试拍汇报里告诉用户，不另增确认点。
3. **钩子库**：反常识问句、结果先行、前后对比、具体数字、局部特写谜面、“如果……”、冲突瞬间；多个方案各用不同的钩子（例句见 `story_structures.md`）。
4. **研究前置 + 来源编号**：事实和卖点从 2.1 开始就带 F# 进剧本，而不是最后才核对。
5. **贯穿物、声音转折是推荐项**：缺少给黄灯，在交付说明里写理由（见 2.5、2.7）。
6. **版本迭代**：script.md 带版本号，STORY_QC.md 记录每版分数和改了哪几拍；用户意见只改对应的拍。
7. **不增加用户负担**：故事层最多 3 次确认并替代原来 1 次（见全程确认点清单）；故事验收由审阅 agent 内部完成；用户说“你定”就全按推荐，交付时报告分数。
8. **系列化复用**：主角卡、世界卡、品牌卡可在同账号系列片之间复用（`casts/`、`brands/` 和现有的 `styles/` 并列）。

## 七、三个示例（只说明每一步怎么用，不含编造的数据）

填好并 lint 过的两支（功能演示 30 秒、科普 90 秒）在仓库根目录 `examples/`，不在技能目录里。下面仍是步骤说明，不是那两支的全文。

### 示例 A：功能演示（30 秒竖屏，主题：Hyperlens 的“选择卡”）
- 时长档 15–<45 秒：2.1、2.2 写进 STORY.md；2.4 + 2.5 合并成主角与世界卡；2.6 并入 2.7；确认 2 次（①、③）。HTML 路线，没有确认④⑤，全程共 3 次。
- 2.1 素材：只用 SKILL.md 里写明的事实：收到题目先发一张选择卡，最多 8 题，前 5 题固定（时长、画幅、风格、参数、交付物），说“你定”就采用推荐项。
- 2.2 观众问题：“AI 做视频为什么老是做偏？”→ 答案：“因为开拍前没问清楚。”揭晓方式：结果先行型（开头先给“一张卡问完”的画面）。目标：想试一下。
- 2.3 方案：每个方案的画风一行写中心画面创意（例：光标贯穿变形）。
- 2.4 主角：用户画像“第一次让 AI 做视频的人”+ 产品即主角（选择卡）；贯穿物是一个光标。
- 2.5 世界：界面状态 3 个（输入题目 → 选择卡逐题勾选 → 镜头表出现）；元素：选择卡、光标、推荐标记。
- 2.7 剧本骨架：结果先行（一张卡问完）→ 卡住（AI 直接出了一段跑偏的片子）→ 旧办法（来回追问修改）→ 产品介入（光标逐题勾选）→ 结果（镜头表出现）→ 下一步（安装链接，由用户提供）。
- 2.8 预定后端：全部 HTML。
- 2.9 ×2 项：真实、可拍性、结尾。

### 示例 B：教程（60 秒横屏，主题：用 ffmpeg 从成片里抽一帧检查画面）
- 时长档 45–<90 秒；按题材改写：2.3 出 2 个方案，2.4 写成一行“你”（写进 world.md），其余步骤都做；故事层确认 3 次（①②③），终端录屏/HTML 路线没有④⑤。
- 2.1 素材：命令行、开源、不需要账号，按教程实测规则在 box 上实跑 SKILL.md 里的命令 `ffmpeg -ss 5 -i output/final.mp4 -frames:v 1 frames/t05.png`，记录真实输出；“常见坑”（例如 `-ss` 写在 `-i` 前面还是后面的区别）实测后才写进剧本，没测的标 `[未实测]`。
- 2.2 观众问题：“我怎么快速检查成片第 5 秒长什么样？”→ 答案：一条命令。揭晓方式：结果先行型。
- 2.5 世界：界面状态（终端空白 → 敲命令 → 文件出现 → 打开图片）；元素：终端、文件夹、抽出的那一帧。
- 2.7 剧本骨架：先看结果（一张抽出来的帧）→ 第 1 步：操作 / 屏幕结果 / 为什么 → 第 2 步 → 常见坑 → 再看结果。
- 2.8 预定后端：终端录屏或 HTML。
- 2.9 ×2 项：可复现、每步有结果、节奏与信息密度。

### 示例 C：历史/科普（90 秒横屏，主题：《人类简史》的一个核心论点）
- 时长档 ≥90 秒：全做，分 2 幕（每幕约 45 秒）；2.9 每幕打分再整片打分；故事层确认 3 次（①②③），用了 AI 图和视频，所以还有④⑤，全程 6 次。
- 2.1 事实卡只用书中广为人知的论点，字幕标“赫拉利认为”：约 7 万年前的认知革命让智人能谈论和相信“不存在的东西”，陌生人因此能大规模合作；书中还提到同时代存在过多种人类。
- **来源怎么拿**：box 上没有这本书。按顺序取：(1) 请用户提供原书页码或截图（可以和确认①一起问）；(2) 出版社或作者公开的书摘、演讲；(3) 都拿不到时不标页码，只标“赫拉利《人类简史》第一部分的观点”，不逐字引用原文。事实卡里写清用的是哪一种来源。
- 2.2 观众问题：“我们不是最强壮的人，为什么最后只剩我们？”→ 答案（书中观点）：因为我们会讲故事，并且一起相信它。揭晓方式：悬念型。
- 2.4 主角：一位讲故事的智人（虚构），只拍手、背影和篝火剪影；视觉锚点：手上的赭红颜料。贯穿物：红手印。
- 2.6 节拍：第 1 幕：钩子（手按上岩壁 + 抛出问题）→ 但是我们不占优 → 所以硬拼会输；第 2 幕：但是那晚有人讲了一个故事（转折）→ 于是陌生人一起按下手印（回答）→ 结尾回到今天：“让你相信一张纸值钱的，也是故事。”
- 2.8：“手按岩壁”“一起按下手印”标为关键镜头，预定后端是先用 AI 图锁关键帧，再图生视频。
- 2.9 ×2 项：真实、因果链、结尾；事实与观点分开写。
