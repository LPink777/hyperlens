# STORYLINES.md（2.3 方案）

推荐方案 1。三个方案在结构、主角类型、钩子类型上都不相同。

## 方案 1（推荐）：光标先把卡点亮

- logline：一张选择卡想被勾完，可是片子已经在旁边跑偏；光标逐题勾完，镜头表才展开。
- 结构模板：结果先行 → 卡住 → 旧办法 → 产品介入 → 下一步
- 钩子画面 + 第一句：卡片第一格被点亮。「开拍之前，先问完。」
- 主角类型：产品即主角（选择卡）+ 用户画像（光标代表人）
- 冲突：没勾完，成片已经开始错位
- 转折：光标从乱晃改成逐格打勾
- 结尾回扣：开头那张卡收拢，展开成镜头表
- 画风一行（中心画面创意，不再另出三个创意）：一枚橙色光标贯穿全片，点亮、被挡住、再停到表上
- 声音一行：勾选是短促的一声；跑偏时声音骤停
- 可拍性风险：低。全部 HTML，文字后期字幕，不依赖模型写字
- 推荐理由：观众问题是「为什么做偏」。先给「问完」的结果，再让人看见没问的后果，最直接回答这个问题。
- 标杆：公开可见的苹果发布会单物件演示。学什么：一个物件从头用到尾，动作说明功能。不拿什么：实拍质感、品牌音乐、产品摄影。

## 方案 2：先播一条做偏的片子

- logline：观众先看见一条对不齐题目的片子，再倒回去看那张还没填的卡。
- 结构模板：痛点开头的悬念，而不是结果先行
- 钩子画面 + 第一句：错位的镜头条挤出画面。「这就是没问就拍的结果。」
- 主角类型：只有用户画像，选择卡后半才出现
- 冲突：观众不知道该怪题目还是怪工具
- 转折：倒回空白选择卡
- 结尾回扣：错位的镜头条变回整齐的表
- 画风一行：中心画面是「错位的成片」，光标不是主角
- 声音一行：开头就是嘈杂快放，后半才安静
- 可拍性风险：低，仍是 HTML；但开头 3 秒像故障片，竖屏上不容易看清「偏在哪里」

## 方案 3：你自己对着清单勾

- logline：第二人称把观众写成正在勾选的人，卡片只是清单。
- 结构模板：前后对比（勾之前 / 勾之后两张静帧来回切）
- 钩子画面 + 第一句：空清单和满清单各占一半屏幕。「你还没选，它就开始拍了。」
- 主角类型：观众「你」
- 冲突：清单上的空格
- 转折：空格被填满
- 结尾回扣：满清单变成镜头表
- 画风一行：中心画面是左右分屏，没有贯穿的光标
- 声音一行：几乎无声，只在填满时一声
- 可拍性风险：低，但是分屏在 9:16 上字会挤；也少了「一个物件在动」的承接
